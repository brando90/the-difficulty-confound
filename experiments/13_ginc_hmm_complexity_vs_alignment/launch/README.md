# Launching 13-GPU (360 shards, about 250 A100-hours)

**Doc link:** <https://github.com/brando90/the-difficulty-confound/blob/main/experiments/13_ginc_hmm_complexity_vs_alignment/launch/README.md>

1. **SNAP (Stanford Network Analysis Project) first.** Use the graphics processing unit (GPU) nodes reached by direct secure shell (SSH): skampere1 (8×A100-80GB), skampere2 (8×H200), skampere3 (8×B200), or mercury1/2 (10×RTX A4000 16GB, small and medium shards 0–239 only, with `MIN_FREE_MB=12000`). Koyejo-group Slurm is not available. Log in once with `ssh <sunet>@skampere2.stanford.edu` (through whale.stanford.edu off campus). **Never retry a failed login in a loop: whale and Sherlock ban IPs.**
2. **Clone at the frozen commit, once, on DFS:** `mkdir -p /dfs/scratch0/$USER/tdc_exp13 && cd /dfs/scratch0/$USER/tdc_exp13 && git clone --branch exp13-ginc-hmm https://github.com/brando90/the-difficulty-confound.git && cd the-difficulty-confound && git checkout --detach <sha> && export TDC_COMMIT=<sha>`. `<sha>` is in `CKPT_ginc_hmm.md`: the freeze SHA for the pilot, the "GPU pilot disclosure" SHA for everything after.
3. **Pilot (9 jobs), then the rates commit:** `MODE=pilot bash experiments/13_ginc_hmm_complexity_vs_alignment/launch/snap.sh skampere2 0 8`. When all 9 are DONE, run `~/venvs/tdc_exp13/bin/python experiments/13_ginc_hmm_complexity_vs_alignment/expt_v1/run.py --arm gpu --pilot-select /dfs/scratch0/$USER/tdc_exp13/runs/gpu_v1/pilot`. The "GPU pilot disclosure" commit (PROMPT.md step 8) records the printed multipliers. Fetch it and check out its SHA.
4. **Shards:** `bash experiments/13_ginc_hmm_complexity_vs_alignment/launch/snap.sh skampere2 0 239` on skampere2 and `... snap.sh skampere1 240 359` on skampere1. The script checks the host, the commit, free GPUs, disk (300 GB on DFS, 20 GB in `$HOME`), the virtual environment and `--check-only`, then starts one tmux window per free GPU in session `tdc_exp13`. Brando's agents may instead run `bash ~/agents-config/scripts/snap_health.sh --node skampere2`, then `SNAP_HOST=skampere2 bash ~/agents-config/scripts/snap_dispatch.sh run tdc_exp13 'cd /dfs/scratch0/$USER/tdc_exp13/the-difficulty-confound && TDC_COMMIT=<sha> bash experiments/13_ginc_hmm_complexity_vs_alignment/launch/snap.sh skampere2 0 239'`.
5. **Progress:** `tmux attach -t tdc_exp13`; `ls /dfs/scratch0/$USER/tdc_exp13/runs/gpu_v1/shards/*/DONE | wc -l`; `logs/status_<host>.tsv` lists exit codes. Rerunning the same command resumes: DONE shards are skipped. A crashed shard keeps its claim and is never retried automatically: move its partial folder aside, `rm -r` its `claims/<id>`, log it in CKPT, and rerun.
6. **Sherlock fallback (Slurm, never compute on login nodes):** clone the same way into `$SCRATCH/tdc_exp13`, then `cd $SCRATCH/tdc_exp13 && mkdir -p slurm_logs && sbatch --export=ALL,TDC_COMMIT=<sha> the-difficulty-confound/experiments/13_ginc_hmm_complexity_vs_alignment/launch/sherlock.sbatch` (array `0-359%16`; for the pilot add `--array=0-8` and `MODE=pilot` to `--export`). Check `module avail python` (default `PY_MODULE=python/3.12`) and `sh_node_feat -p gpu | grep GPU_SKU`. Watch with `squeue -u $USER`. `$SCRATCH` is purged after 90 days unmodified: copy finished results to `$GROUP_HOME` or Oak, and never touch files to dodge the purge.
7. **Verify, then collect:** rerun either launcher with `MODE=verify` (writes VERIFIED markers). Then `run.py --arm gpu --merge <OUT>` writes `expt_v1/results/gpu/` without checkpoints. rsync it to the coding agent's clone (`rsync -av --exclude checkpoints/ ...`) or commit it on branch `exp13-ginc-hmm`. Checkpoints (about 275 GB) stay on cluster storage; their SHA-256s travel in the DONE files.

**TLDR-end:** [tdc: Expt 13 launch] Run the 9-job pilot and then the 360 shards of 13-GPU on SNAP GPU nodes with `snap.sh` (tmux, one process per free GPU, resumable claims) or on Sherlock with the `sherlock.sbatch` array, verify every shard, and merge results without checkpoints back to the branch.
