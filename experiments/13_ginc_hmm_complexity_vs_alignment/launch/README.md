# Launching 13-GPU (360 shards, about 250 A100-hours)

**Doc link:** <https://github.com/brando90/the-difficulty-confound/blob/main/experiments/13_ginc_hmm_complexity_vs_alignment/launch/README.md>

`<code sha>` is the "Experiment 13 GPU code" commit (the pilot runs there) and `<pilot sha>` the "Experiment 13 GPU pilot disclosure" commit (every shard and verify job runs there); both are in `CKPT_ginc_hmm.md`. The GPU environment is torch 2.6.0 (cu124 on Sherlock, cu126 on SNAP) with `requirements-gpu.txt`; B200 nodes are not supported by that torch.

1. **Clone once, then check out the commit.** `git clone --branch exp13-ginc-gpu https://github.com/brando90/the-difficulty-confound.git && cd the-difficulty-confound && git checkout --detach <sha>`. SNAP: in `/dfs/scratch0/$USER/tdc_exp13`. Sherlock: in `$SCRATCH/tdc_exp13` (run `ml load system git` first; the system git is too old).
2. **Concepts and references, once (CPU).** They go to `expt_v1/prep/gpu` and every GPU job reads them. Sherlock: `cd $SCRATCH/tdc_exp13 && mkdir -p slurm_logs && sbatch --export=ALL,TDC_COMMIT=<code sha> the-difficulty-confound/experiments/13_ginc_hmm_complexity_vs_alignment/launch/sherlock_prep.sbatch` (about 10 min, also builds the virtual environment and runs the unit tests). SNAP: `snap.sh` runs `--check-only` itself the first time.
3. **Pilot (9 jobs).** Sherlock: `sbatch --array=0-8 --dependency=afterok:<prep job id> --export=ALL,MODE=pilot,TDC_COMMIT=<code sha> .../launch/sherlock.sbatch`. SNAP: `MODE=pilot TDC_COMMIT=<code sha> bash experiments/13_ginc_hmm_complexity_vs_alignment/launch/snap.sh skampere2 0 8`. When all 9 are DONE: `python expt_v1/run.py --arm gpu --pilot-select <OUT>/pilot` prints `gpu.lr_selected`. The "GPU pilot disclosure" commit records it (config key plus a PROTOCOL Section 7 paragraph, nothing else); pull it and check out `<pilot sha>`. The prep folder is untracked and survives the checkout.
4. **Shards (0–359).** Sherlock: the gpu QOS takes at most 100 submitted jobs per user, so submit in chunks, each after the previous one has drained (or chained with `--dependency=afterany:<previous array id>`): `sbatch --array=0-95%16 --export=ALL,TDC_COMMIT=<pilot sha> .../launch/sherlock.sbatch`, then `96-191%16`, `192-287%16`, `288-359%16`. SNAP: `TDC_COMMIT=<pilot sha> bash .../launch/snap.sh skampere2 0 239` and `... snap.sh skampere1 240 359`. Never log in in a loop: whale and Sherlock ban IPs.
5. **Progress.** `squeue -u $USER` (Sherlock, at most once a minute) or `tmux attach -t tdc_exp13` (SNAP); `ls <OUT>/shards/*/DONE | wc -l`; `<OUT>/logs/status_*.tsv` lists exit codes. A rerun skips DONE shards. A crashed shard keeps its claim and is never retried automatically: move its partial folder aside, `rm -r <OUT>/claims/<id>`, log it in CKPT, resubmit that index.
6. **Verify every shard on a GPU.** Same launcher with `MODE=verify` (same chunks). Each job checks the DONE hashes, regenerates the training stream, replays every checkpoint in float64 and writes `VERIFIED`.
7. **Merge and copy back.** On a CPU node: `python expt_v1/run.py --arm gpu --merge <OUT>` writes `expt_v1/results/gpu/` without checkpoints (their SHA-256s go to `checkpoint_sha256.json`). Copy that folder to the analysis clone (`rsync -av --exclude checkpoints/`), then `verify.py --arm gpu`, `analyze.py --arm gpu --stage 1`, `--stage 2`. Checkpoints (about 275 GB) stay on cluster storage: `$SCRATCH` is purged after 90 days unmodified, so copy them to `$GROUP_HOME` or Oak and never touch files to dodge the purge.

**TLDR-end:** [tdc: Expt 13 launch] Build the 13-GPU concepts once on a CPU node, run the 9-job learning-rate pilot at the GPU code commit, record the chosen rates in the pilot disclosure commit, then run, verify and merge the 360 shards on Sherlock (Slurm arrays in chunks of at most 100) or SNAP (tmux, one process per free GPU).
