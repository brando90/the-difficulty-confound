# Launching 16b (240 shards, about 90 A100-hours)

**Doc link:** <https://github.com/brando90/the-difficulty-confound/blob/main/experiments/16_carry_alignment_crossed_arithmetic/launch/README.md>

1. **SNAP (Stanford Network Analysis Project) first.** Use the graphics processing unit (GPU) nodes reached by direct secure shell (SSH): skampere1 (8×A100-80GB), skampere2 (8×H200), skampere3 (8×B200), or mercury1/2 (10×RTX A4000 16GB, best for the 1M and 6M shards 0–119 and 180–239). Koyejo-group Slurm is not available. Log in once with `ssh <sunet>@skampere1.stanford.edu` (through whale.stanford.edu off campus). **Never retry a failed login in a loop: whale and Sherlock ban IPs.**
2. **Clone at the frozen commit, once, on DFS:** `mkdir -p /dfs/scratch0/$USER/tdc_exp16 && cd /dfs/scratch0/$USER/tdc_exp16 && git clone --branch exp16-carry-crossed https://github.com/brando90/the-difficulty-confound.git && cd the-difficulty-confound && git checkout --detach <sha> && export TDC_COMMIT=<sha>`. `<sha>` is in `CKPT_carry_crossed.md`: the freeze SHA for the pilot, the "GPU pilot disclosure" SHA for everything after.
3. **Pilot (9 jobs), then the disclosure commit:** Run `MODE=pilot bash experiments/16_carry_alignment_crossed_arithmetic/launch/snap.sh skampere1 0 8`. When all 9 jobs are DONE, run `~/venvs/tdc_exp16/bin/python experiments/16_carry_alignment_crossed_arithmetic/expt_v1/run.py --arm transformer --pilot-select /dfs/scratch0/$USER/tdc_exp16/runs/transformer_v1/pilot`. It prints the learning rates and whether plain format stays primary. Those values go into the "GPU pilot disclosure" commit (PROMPT.md step 7). Fetch it and check out its SHA.
4. **Shards:** for example `bash experiments/16_carry_alignment_crossed_arithmetic/launch/snap.sh skampere1 120 179` (the 25M shards) on skampere1, and `... snap.sh mercury1 0 119` and `... snap.sh mercury2 180 239` on the mercury nodes. The script checks the host, the commit, free GPUs, disk (55 GB on DFS, 20 GB in `$HOME`), the virtual environment and `--check-only`. It then starts one tmux window per free GPU in session `tdc_exp16`. Brando's agents may instead run `bash ~/agents-config/scripts/snap_health.sh --node skampere1`, then `SNAP_HOST=skampere1 bash ~/agents-config/scripts/snap_dispatch.sh run tdc_exp16 'cd /dfs/scratch0/$USER/tdc_exp16/the-difficulty-confound && TDC_COMMIT=<sha> bash experiments/16_carry_alignment_crossed_arithmetic/launch/snap.sh skampere1 120 179'`.
5. **Progress:** `tmux attach -t tdc_exp16` shows the workers. `ls /dfs/scratch0/$USER/tdc_exp16/runs/transformer_v1/shards/*/DONE | wc -l` counts finished shards. `logs/status_<host>.tsv` lists exit codes. Rerunning the same command resumes and skips DONE shards. A crashed shard keeps its claim and is never retried automatically. To rerun it: move its partial folder aside, `rm -r` its `claims/<id>`, log it in CKPT, then rerun.
6. **Sherlock fallback (Slurm; never compute on login nodes):** Clone the same way into `$SCRATCH/tdc_exp16`. Submit: `cd $SCRATCH/tdc_exp16 && mkdir -p slurm_logs && sbatch --export=ALL,TDC_COMMIT=<sha> the-difficulty-confound/experiments/16_carry_alignment_crossed_arithmetic/launch/sherlock.sbatch` (array `0-239%16`). For the pilot, add `--array=0-8` and put `MODE=pilot` in `--export`. Check `module avail python` (the default is `PY_MODULE=python/3.12`). Watch with `squeue -u $USER`. `$SCRATCH` is purged after 90 days unmodified. Copy finished results to `$GROUP_HOME` or Oak, and never touch files to dodge the purge. The CPU arm 16a can also run there as one `normal`-partition job (PROTOCOL Section 7).
7. **Verify, then collect:** Rerun either launcher with `MODE=verify`. Then `run.py --arm transformer --merge <OUT>` writes `expt_v1/results/transformer/` without checkpoints. Rsync that folder (`rsync -av --exclude checkpoints/ ...`) to the coding agent's clone, or commit it on branch `exp16-carry-crossed`. Checkpoints (about 47 GB) stay on cluster storage.

**TLDR-end:** [tdc: Expt 16 launch] Run the 9-job learning-rate pilot and then the 240 shards of 16b on SNAP GPU nodes with `snap.sh` (tmux, one process per free GPU, resumable claims) or on Sherlock with the `sherlock.sbatch` array, verify every shard, and merge results without checkpoints back to the branch.
