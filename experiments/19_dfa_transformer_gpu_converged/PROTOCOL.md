# Protocol: Experiment 11's transformer grid trained to convergence on a GPU (`19_dfa_transformer_gpu_converged`)

Status: frozen on 10-19-2026 before any Experiment 19 training. No GPU run of this code and no pilot has happened. Seen before writing this: Experiment 11's full results (RESULTS, every gate, the exploratory LSTM arm) and Experiment 13-small's elasticity ratio E = 0.80 [0.79, 0.83]. After the freeze commit nothing in Sections 2–5 changes; deviations go in RESULTS.

## 1. Question

Experiment 11 asked whether, in units of data, the target's share α moves the data bill more than exact DFA complexity K does (C2, gate G4: elasticity ratio E = e_α / e_K > 1). Its 104,002-parameter transformer barely learned within 2^16 examples: 104 of 128 α = 1 runs never got below 0.5 bits, every T*-based number was set by the cap, and E came out 0.083 [0.078, 0.090] at ε* = 0.5 bits. Experiment 13-small (HMMs, a learner that did train) gave E = 0.80 [0.79, 0.83]. Both are below 1, the opposite of "alignment dominates".

**This experiment asks one thing: is E < 1 an artefact of under-training?** It reruns Experiment 11's grid with the same model, initialization, optimizer, tasks, test set, seeds and α values, trained up to 64 times longer (to 2^22 examples), and reports E with its interval next to 0.083 and 0.80.

## 2. Prediction (written before any run)

- **P1.** At α = 1, the n = 4 and n = 8 targets reach ≤ 0.1 bits by 2^20 examples in most seeds. The n = 32 targets do not reach 0.3 bits by T_top.
- **P2.** The convergence criterion (Section 5) is met at α = 1, mostly because the n ≥ 16 runs flatten ("stalled": converged above 0.1 bits) rather than because they learn.
- **P3 (the headline).** E (K in bits, at the primary ε*) stays below 1 with its upper bound below 1: under-training does **not** explain E < 1. E rises above Experiment 11's 0.083 (less capped) and stays in [0.1, 0.8]. Subjective probability about 0.7.
- **P4.** G5 (the complexity gap shrinks with training) stays NOT_ESTABLISHED.
- **P5.** η < 1 (distractors transfer) persists.

## 3. Design

### 3.1 Unchanged from Experiment 11 (its PROTOCOL Sections 2.1–2.5)

The 32 tasks (16 targets, 16 distractors) read from Experiment 11's `results/tasks.json`; the hash train/test split; the shared 4,096-string test set (regenerated by Experiment 11's `data.build_test_set` and checked byte for byte); the 2-layer, d = 64 transformer (`model.build_model`, 104,002 parameters); initialization (`torch.manual_seed(seed)` then `build_model`, so each seed's 64 cells start from Experiment 11's weights for that seed); AdamW at 10^-3, weight decay 0.01, betas (0.9, 0.999), 8-step linear warmup then constant; batch 64 with one string length per batch; gradient-norm clip 1.0 per model; seeds 11101–11808; α ∈ {0.05, 0.15, 0.4, 1.0}; the six laws, both fitters, the bootstrap and every gate threshold.

### 3.2 Changed

1. **Length of training.** Checkpoints at every power of two from 2^9 to 2^22 (steps 8 to 65,536), not 2^9 to 2^16. The run stops early only under the budget rule (3.3); T_top is the last finished checkpoint.
2. **Fresh data.** Each example is a fresh uniform string from the train partition (rejection against a lookup table of the hash split for every length 8–24, checked against `data.in_test_partition`), not a draw from a fixed 4,096-per-length pool. At 2^22 a pool would be reused about 60 times, which would mix memorization into the data bill.
3. **Exact share after every step.** After every step the cell has seen exactly round(α·T) target examples (Experiment 11: exact per octave). Target slots sit at random positions in the batch; the distractor slots cycle through a fixed per-cell permutation of the 16 distractors, so distractor counts are equal to ±1 at every T.
4. **Length schedule.** Balanced over lengths 8–24 and shuffled per seed, shared by the seed's 64 cells (Experiment 11: per cell).
5. **Hardware and batching.** All cells train side by side in one process on one GPU, float32 with TF32 off. Parameters are stacked on a model axis; `ensemble.py` computes exactly Experiment 11's forward pass. `test_ensemble.py` checks on the CPU that the forward pass matches `model.py` within 1e-5, that five AdamW steps with warmup and active clipping match five separate `model.py` steps within 2e-5, that labels match `dfa.run_dfa`, that the lookup table matches the hash split, and that the share schedule is exact.
6. **Artifacts.** One predictions file and one checkpoint file per T for all cells, instead of per-cell files.

### 3.3 GPU budget and subset rule

Brando has about 5.9 GPU hours left of 8, shared with AT-441's Putnam-to-GSM8K pilot, which runs first.

- **Cap.** At job start, `launch/budget.py` reads the GPU hours AT-441's pilot array actually used (sacct; running or pending jobs count at their time limit) and sets this run's wall cap to min(105 min, (5.9 − used) × 60 − 15 min). Under 30 minutes it does not train.
- **Octave rule.** After each checkpoint the run projects the next octave from the last octave's step time (+5%, plus one evaluation and one minute) and stops cleanly if that would pass the cap.
- **Subset rule.** At T = 2^12, if the measured speed says the full 8-seed grid cannot reach 2^19 within the cap, seeds 11505, 11606, 11707 and 11808 are dropped and training continues with seeds 11101–11404 (all 16 targets × 4 α each). The skipped cells (every cell of the dropped seeds after 2^12) are named in `run_state.json` and RESULTS, and the analysis uses the 4 kept seeds only.
- GPU hours actually used come from sacct for the training job (`gpu_usage.json`).

## 4. Analysis

`analyze.py` is Experiment 11's, with three changes: `realize()` sets the T-dependent keys from the finished run, `read_rows` keeps only the seeds used, and `eps_star_levels` is {0.5, 0.3, 0.1, 0.03}.

1. **T keys.** Fit cells use T ≤ T_top/2; T_top is the held-out extrapolation slice (with K = 16 and α = 0.15 as before); the plateau reference is T_top/4 and the G5 gap reference T_top/16 (Experiment 11: 2^14 and 2^12 for T_top = 2^16).
2. **Primary ε\*** (mechanical, in stage 2, before any gate is computed): the smallest of {0.1, 0.3, 0.5} bits that at least half of the 16 targets reach at α = 1 in the median seed; if none, 0.5. The G4 model-free fallback is the next coarser level (0.3, 0.5 or 0.7). E is reported at every level, and E at 0.5 bits is the like-for-like comparison with Experiment 11's 0.083.
3. Everything else (held-out scoring, frozen forecasts, seed-block and two-stage bootstraps, gates G1–G7) is Experiment 11's code unchanged.

## 5. Convergence criterion and the verdict

- **Run converged** at T_top if ε(T_top) ≤ 0.02 bits, or ε(T_top/2) − ε(T_top) ≤ 0.02 bits (the last doubling of data bought at most 0.02 bits). A converged run with ε(T_top) > 0.1 bits is reported as *stalled*, one at ≤ 0.1 bits as *learned*.
- **Grid converged** if at least 90% of α = 1 runs and at least 75% of all runs are converged.
- **Verdict on "does under-training explain E < 1?"** (law-based E, K in bits, primary ε*, seed-block 95% interval):
  - grid converged and lower bound > 1: **yes**, once trained alignment dominates;
  - grid converged and upper bound < 1: **no**, complexity still costs more data per log-unit after convergence;
  - grid converged and the interval contains 1: **undecided**;
  - grid not converged: the caveat is **not removed**; report how far training got.
- If most n ≥ 16 runs are *stalled* well above 0.1 bits (which the LSTM arm of Experiment 11 says the data allow), the complexity effect is the 2-layer transformer's capacity, not a data cost, and RESULTS must say so (Experiment 11 PROTOCOL Section 6).
